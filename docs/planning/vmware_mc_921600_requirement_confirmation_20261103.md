# VMware 与 MC 业务串口改为 921600 baud

## 1. 原始指令与目标

> 还有一个需求。把VMware和MC之间的串口波特率修改到921600。

本条为独立需求：**VMware 中运行的 SoC/AP 软件与真实 MC 之间的业务串口，两端统一使用 921600 baud。**用户已指定目标速率；以下实施概要待 ARCH/相关 Owner 核实，按准确版本进入既定审批流程，不重复询问目标数值。

本单归档需求及交接建议，不代表已自动入队、派单、修改运行配置或固件、完成测试。与[MC/TH Debug 模式需求](mc_th_debug_mode_requirement_confirmation_20261103.md)分别管理，可在后续组合联调中对账。

## 2. 本地观察与范围

本轮只读观察：AP 的 [VMware 服务配置](../../../soc-ap/config/runtime/vmware/services_manifest.json)和[公共服务配置](../../../soc-ap/config/runtime/common/services_manifest.json)中 `baud_rate` 为 115200；[VMware 联调说明](../operations/vmware_twin_joint_debug.md)和[物理联调 SOP](../operations/ap_mc_th_joint_debug.md)也包含该链路的 115200 示例。它们不证明当前部署或 MC 板上实际值；实施前应核实准确候选、配置覆盖顺序和现场固件。

- 修改范围由 ARCH 明确到 VMware/AP 运行配置、必要串口适配和 MC 对应业务 UART 初始化；两端必须配套发布和部署。
- MC↔TH 是另一条物理链路，MC/TH 的调试串口也各自独立。本需求不自动要求它们改变波特率；若发现吞吐、共享配置或外设时钟依赖，由对应 Owner 提交影响分析。
- 核查同一 MC UART 在 App、升级及 Bootloader 阶段的用途和速率切换。不能把 App 改速率等同于升级链路已兼容，也不据本需求擅自修改 Bootloader。
- 其余串口参数按已接受契约保留；USB 转串口适配器、Linux 驱动、VMware USB 透传和 MCU 时钟/分频的实际支持均需核实。不能仅凭设置接口返回成功就认定线路以目标速率可靠工作。
- 保持通信协议、ACK/超时和设备保护语义。需要调整缓冲、DMA/中断或超时参数时，先给出依据和有界改动，不借提速扩大重构或引入大依赖。

## 3. 实施概要与角色

| 角色 | 建议工作 |
| --- | --- |
| ARCH | 确认物理链路、两端串口配置来源、模式切换、兼容/回退办法及验收负载和期限 |
| ENG-FWD | 核查 AP 串口设置能力、启动参数覆盖及错误处理，负责其模块内必要改动 |
| ENG-MC | 核查并修改 MC App 对应 UART，确认实际时钟配置和接收/发送能力 |
| INTEGRATOR | 按配置文件所有权装配 VMware 发布配置，统一部署、启动入口、诊断命令和联调文档；锁定配套候选及回退组合 |
| 独立 QA | 编制正例、相关负例及恢复验收，审阅同一候选的独立软件与真实 HIL 证据 |

公共配置是否同时改变、其他平台如何保持正确，由 ARCH/INTEGRATOR 根据继承关系判断；不直接全局替换所有 `115200`。共享文件指定唯一 Owner。Bootloader 或 TH 若确有依赖，另由对应角色处理明确范围，不由 FWD/MC 作者跨界修改。

COORD 查重并关联现有串口任务；目标数值沿用本次用户指令，细化实施概要和真正未决的范围取舍按既定流程处理。正式任务、实际会话、白名单、分支和候选由 COORD 登记，本单不代填。

## 4. 验收与交付

1. **配置生效**：从正式启动入口运行，确认有效参数及 MC UART 配置对应 921600，排除旧默认值/命令行覆盖；绑定适配器、设备、固件与配置身份。
2. **正常用户流程**：在 VMware 的 Web UI 查询 MC/TH 版本和实时温度，验证 MC 双向通信及适用的 TH 中继正常，页面真实更新且符合既定期限。TH 中继回归不等于要求修改 MC↔TH 波特率。
3. **连续负载**：按事前冻结的消息频率、持续时间和错误/资源判据检查 CRC、丢帧、超时、重试及缓冲溢出；921600 与 Debug 模式同时开启时，增加组合回归，防止调试输出拖慢业务。
4. **异常与恢复**：验证批准范围内的速率不匹配、USB 断开/重连和服务/MC 重启；错误显式上报、UI 如实降级，恢复到匹配配置后正常通信。不用静默降速掩盖目标速率失败。
5. **切换与升级兼容**：核实配套部署顺序、失败回退入口及适用的固件升级路径，避免 App 可用但升级入口失联；涉及硬件的操作由授权操作者在已登记窗口执行。

保存 AP/MC 准确服务器候选、配置和固件哈希、启动/部署记录、业务串口双向原始物证、相关调试日志、浏览器步骤与断言、实际负载及统计结果。软件检查与真实 HIL 分别记录，按[交付门禁](../../.agents/rules/delivery_and_coord_gate.md)及[独立 QA 规则](../../.agents/rules/codex_qa_review.md)收件。尚未执行的项目保持未执行；真实验收失败生成/关联 Issue，修复后以新候选复验。
