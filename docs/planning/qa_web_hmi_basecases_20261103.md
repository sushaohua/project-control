## 1. 来源与用例冻结

本专项采用的策略须在任务卡明确：新卡 `qa_policy: streamlined-v1`，单轮独立 QA 审查代码和功能/回归证据；QA 自编用例/预期/工具须非作者独立检查，不递归增加报告复核。未迁移旧卡保留 legacy 门禁。

basecase 覆盖手册 9 类功能及 7 阶段用户旅程，PM/ARCH 将每项映射至正式需求/准确 revision 和接受依据，独立 QA 据此细化自动化。未接受或不稳定的手册描述先作为候选 base，不能仅凭手册存在认定已稳定实现。产品范围内缺功能记失败，需求歧义阻塞相关断言，冻结项说明依据，禁止失败后删项。

手册仅用于用户动作与预期线索，以下不直接作固定黄金值：地址、版本/短 hash、示例温度、模型层数、5×5 具体高度、HMS 示例错误码、按钮选择器、所谓“瞬时/毫秒级”及“零风险”描述。预期来源顺序为实际用户批准/现行正式需求、已接受契约及适用工程门禁，再与手册对账；冲突记录澄清，不以当前实现输出倒推正确答案。

执行前必须解决或登记以下来源差异；有明确高层门禁的先遵守门禁，额外产品承诺交 PM/ARCH 确认：

| 澄清项 | 观察与处理 |
| --- | --- |
| 断线 CPU | 手册功能 9 写 ≤1%，现行工程门禁为 ≤2%；测量口径/进程/采样窗口同样待冻结。保留两者来源，产品是否承诺更严阈值由 PM/ARCH 明确，不静默替换 |
| 断线及重连期限 | 手册 3s 断线、1.5s 重连与部分旧 SOP 的 STALE/FAULT 分段描述须对齐；安全降级至少遵循现行强门禁，其他指标不靠脚本随意设定 |
| 作业进度 | 手册“匀速旋转”不能覆盖硬件 ACK/执行推进规则；用例校验真实执行依据、暂停/断线停止与最终完成，不接受本地计时器假进度 |
| Option A 的物理能力 | 加热 0% 不代表运动/供料/探针已具备或无风险；分别核实输出保护、限位、真实位移、探针和供料效果 |
| 固件与在线依据 | 手册中的示例版本/hash 不能固定写进用例；两板分别核对完整源码/制品映射及本轮有效响应 |
| 持久化与数据清理 | 按需求区分浏览器本地完成标志和后端配置持久化；首次 profile、已完成 profile、服务重启各自独立，不能先设置完成标志再测向导 |

每例冻结：`case_id/revision`、`suite`、需求/手册章节、角色、起始页面、前置数据及依赖、逐步操作/预期/期限、正常/故障/恢复、物理效果和证据、失败处理及复位。未给出期限的字段由契约补齐，相关时限断言保持待明确。

## 3. 三个核心用例的逐步规格

下面的 `T_probe / T_sample / T_save / T_nav / T_recover` 等为待绑定契约的期限键，不是脚本默认常量；未接受时不能运行相应时限断言并宣称通过。完整自动化需将其余规格组同样展开，不能用组表代替逐步 case。

| case / 前置 | 用户步骤 | 逐步预期与期限 | 失败/恢复及证据 |
| --- | --- | --- | --- |
| BASE-02-POS；干净 profile、MC/TH 健康，本轮采集在服务冷启动前开始 | 首页→新机引导→下一步→语言选择→设备检查 | 用户可实际点击；触发/取得本轮真实探测，在 `T_probe` 内分别显示两板版本和 ONLINE，AP 同步状态有依据 | 超时 UNKNOWN 记 FAIL，保存 UI/启动/真实 TX/RX/调试日志，提交 Issue；相关后续阻塞，独立例继续 |
| BASE-02-NEG/REC；单独的清洁运行状态 | 未接设备打开同一检查页→确认未就绪→按 SOP 接回设备 | 离线不全绿；重连在 `T_recover` 内发生新探测、版本及在线恢复，旧缓存不满足断言 | 物理动作保留操作者/时戳；恢复失败保留现场，不能在浏览器注入版本 |
| BASE-05-POS/REC；前四步真实满足 | 总结页→完成→观察工作台→刷新→重新打开向导 | `T_save/T_nav` 内反馈/导航；完成标志按契约保持，重开入口可用且不丢用户配置 | 任一无反馈/无导航/未落盘记相应失败；保留点击轨迹、公开返回与刷新结果 |
| BASE-20-POS；温度传感器健康，确认源节点/单位 | 首页→点击温度胶囊→温度面板→观察至少约定数量的新样本 | 在 `T_sample` 内按同一采样关联原始值和 UI，正确换算/舍入并标有效；两板版本独立匹配 | 不使用手册 120.7/24.5 作固定预期；保存采样关联、帧和 UI 读数 |
| BASE-20-NEG/REC；授权故障窗口 | 按 SOP 使一端数据失效→观察→恢复来源 | 按契约失效、锁定相关控制并提示；新有效样本恢复，旧温度不仍显示 FRESH | 记录故障层/持续时间/恢复；加热继续 0%，不为造温度实加热 |

## 4. 首轮增量 delta

## 5. 执行与批准边界

| 用例范围 | 最终接受要求 |
| --- | --- |
| BASE-01/02/04/06 中的真实探测、硬件状态与传感器断言；BASE-20/21/24/25 | 必需真实 HIL，核对实际节点响应、采样/身份或物理故障及恢复；不能用缓存、模拟器在线或生成的日志代替 |
| BASE-07、BASE-10～16 的实际急停、作业、运动、回零、调平断言；BASE-18 的实际通道生效 | 必需真实 HIL 与适用物理效果；真实接收、执行完成和效果分别核对，逻辑坐标/进度变化不独证动作 |
| DELTA-DBG、DELTA-BAUD、DELTA-COMB 的最终功能接受 | 必需真实 HIL，在锁定组合上关联 Web/API、真实业务帧、所涉节点 Debug 和测量/效果；921600 业务链路与调试、级联链路参数分别核实 |
