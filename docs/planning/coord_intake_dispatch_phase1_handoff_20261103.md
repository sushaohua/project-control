# 三类人工入口自动调度第一阶段 COORD 实施交接单

## 1. 交接目标和当前事实

按[第一阶段设计 revision 2](../architecture/coord_intake_dispatch_phase1_design_20261103.md)安排后续工作：人工提交一批指令或 MD，AI 按“一条指令一条需求”形成理解和实施概要；程序生成分类 YAML 及待审批包，绑定实际人工批准后，COORD 拆分多人任务并自动推进。依次接受手动单步、持续推进/恢复、定时服务，人工不维护 YAML。

本单是提供给当前用户转交既有唯一 COORD 的派单准备，不是正式任务卡、Agent 创建记录或 Ready 决定。未分配正式 ID/revision、未启动实际作者/Reviewer、未修改旧任务或看板，也未执行验证。所有待落实会话保持未知，不使用历史 COORD UUID 或计划别名假充当前接收方。

已只读核对 AUTO-01/02、当前队列/Runner/模板及 AUTO-02 run_13 报告范围。现有默认作者执行器仍定位和核验 HEAD，未见三类入口扫描；旧软件接受不能替代本阶段宿主派发和常驻验收。具体本地观察提交见设计 §2，不能直接当服务器验收锁。

## 2. 建议拆分：先调查，再实现，再独立接受

下列 A～E 仅为交接工作项标签；正式任务 ID、revision、工作包关联和状态由 COORD 查重后分配。已有 AUTO 任务记录保留，通过新任务关联其可复用产物。

| 工作项 | 建议岗位 | 输入与本轮唯一目标 | 出口/下游 |
| --- | --- | --- | --- |
| A：需求/方案确认与宿主适配 | PM/ARCH 编制确认单和实施概要，INTEGRATOR 调查接口；独立 QA/Owner 检查 | 用户已确认原则、实际 COORD/宿主及角色工具；提供简短待审批包及准确版本，复用已有有效授权 | 明确原文到需求的映射、审批入口、真实调用和查询；未明确能力不以模拟替代 |
| B：原文输入和机器收件 | INTEGRATOR，独立 QA | 已接受协议；MD 模板、需求确认/分类 YAML、编号去重、实际审批绑定和回执 | 原文不丢约束，一条指令一个需求，人工不维护 YAML，未批准实现不启动 |
| C：真实调度和角色作业 | INTEGRATOR 主责；宿主适配由明确 Owner 承担 | A 的实际适配、B 的有效收件、现有任务/资源/QA 链 | 真实决策、正式任务登记、实际派发、异步查询、结果核对和幂等恢复，不使用默认 HEAD 冒充作者执行 |
| D：独立单步及恢复验收 | 独立 Codex QA；报告由非作者独立复核 | 服务器锁定 B/C 工具和人工准备的三类输入；设计 P1 条款 | 验证三类输入、阻塞隔离、长作业下另一票推进、重复/崩溃/双启动/写冲突和正式门禁 |
| E：定时服务和独立运行接受 | INTEGRATOR 部署；独立 QA 验证和非作者复核 | D 接受的同一执行入口、实际宿主账户/运行目录及服务配置 | 自动唤醒、单实例、无变化不调用模型、停止/重启恢复；明确已部署范围及未完成项 |

调查任务不以尚未产出的实现/签署作为前置；实现和验收分别消费准确已接受输入。B/C 可能共享 tools/coord_runner 和公共配置，首版由单一 Owner 管理共享文件，按实际路径/依赖串并行，不为并行制造相互覆盖。

## 3. 输入、边界与执行要求

- 读取权威[交付门禁](../../.agents/rules/delivery_and_coord_gate.md)、[QA 规则](../../.agents/rules/codex_qa_review.md)、[总控清单](coord_autorun_tasklist_20261029.md)、[角色提示词模板](../../.agents/rules/templates/角色任务提示词.md)及[任务模板](../../.agents/rules/templates/任务卡模板.md)，再绑定准确 revision 和内容哈希。
- 作者及接收方：实际会话、run、模型、COORD 入口、反馈通道和有效租约均待 COORD 落实。原卡中历史人员/租约不能自动续用。
- 默认实施仓库为 project-control；建议范围为 `tools/coord_runner/`、`config/coord_runner/`、必要的 `tools/coord_queue.py` / `tools/check_task_graph.py` / 相关检查、接受后的三类入口目录及本专项证据。精确白名单由每票冻结，不能开放整个工程。
- 本阶段不修改 soc-ap/mcu-p3 业务，不修改 Bootloader，不执行硬件动作，不迁移全部历史任务。test_harness 若确有独立测试资产增量，须另明确 Owner/任务/路径，不把一个工程作者扩为跨仓万能角色。
- 不安装新的后台服务直到单步及恢复范围有独立接受，且实际部署条件、账户、单实例和回退入口已经登记。定时触发只唤醒开发 COORD，不能改变 QA 固定轮次候选。
- 第一阶段由人提供原始 MD/指令及真实审批输入，AI 产生理解与方案，程序生成 YAML；理解确认及实施概要默认合并一次审批，支持部分批准，已有有效批准直接引用。实际工程演练限定在准确获准的小范围软件工作，不能把模拟审批当成真实业务授权。
- 收件回写必须保留旧任务、手工修改、历史签署和未审阅差异；入口与正式任务关联可追踪。任务/Issue 的 Done 或 fixed 仍由适用门禁决定。
- 检查点与预算：沿用现行模型策略、最大实现并发、同因返工上限和任务检查点；具体超时、运行预算、宿主窗口由实施任务接受。权限/资源不足记录解除条件，其他就绪工作继续。

## 4. 交付与验证要求

每票交付准确服务器候选、diff、接口/配置版本、实际运行记录和 P1 条款映射。实施前接受实际验证命令/cwd/预期、非零用例清单和错误判据；本单不提供不存在的自动调度命令，也不以静态检查 exit 0 声称已派发 Agent。

正式 QA 从服务器锁定源码/契约/测试工具，独立容器运行适用软件检查和恢复用例，独立 Codex 审阅同一候选、实际宿主调用证据及输出；QA 报告非作者复核后再由 COORD 接受。宿主集成检查须另提供隔离测试项目/账户、真实调用和交付记录，不在作者工作树里自测后提升为正式 QA。

最小证据至少包括：

1. 人工原文版本/哈希、逐指令到需求的映射、公共约束、生成 YAML、需求确认/方案及实际人工批准绑定，最后关联正式任务。
2. 唯一 COORD 实际会话、决策请求/结果及程序校验记录。
3. 各角色的真实 job/session、任务/revision、输入和交付，尤其一个等待时另一就绪工作实际推进。
4. 派单超时、重复扫描、进程恢复、双实例、租约活跃和写入冲突等原始结果。
5. 同一候选的服务器/沙箱、独立 QA、报告非作者复核和正式收件证据；假会话、HEAD 读取或内部 checkpoint 不能单独替代。
6. 定时阶段实际宿主服务、配置、周期、账户和启动/停止/重启记录；单步接受不自动覆盖服务部署。

设计的 P1-01～P1-20 是最低检查范围，新增一条需求多人完成、部分审批、防伪/旧版本批准及原文增量映射。适用项通过和接受齐备才关闭任务；缺必要条件保持待审/阻塞，不回退 self、不手填 APPROVED。部分能力接受须注明单步/恢复/定时各自范围。

## 5. COORD 开工前需要核实的缺口

| 缺口 | 来源与处理 |
| --- | --- |
| 唯一 COORD 实际入口、宿主支持及 invoke_subagent 可自动调用方式 | 本轮未获取该运行接口；由 A 调查和绑定，不能根据工具名猜测已接通 |
| 可查询的真实角色 job 与不明启动对账 | 当前默认作者执行器不足以提供；A 先接受接口，C 实现 |
| 正式任务 ID、父工作包、范围、当前在途和写入占用 | 只由实际 COORD 查重/核对后登记；不照抄本单 A～E 当正式 ID |
| 作者/独立 Reviewer、准确服务器输入、运行目录及账户 | 实际会话和新任务开工条件尚未落实；不要套用历史签署或租约 |
| 需求确认、实施概要和设计接受 | 用户已确认总体原则，细化包按准确版本供批量审批，已有有效批准复用；独立技术接受和必要 schema/工具适配仍需完成 |

缺口应先形成有界调查并继续不依赖其结果的准备工作。只有实际外部权限/账号或产品决策缺失且团队不能解除时，向用户提出具体事项，不让用户逐票转发技术材料。

## 6. 给现有 COORD 的启动消息

以下供用户转交，本文未自动发送：

```text
你继续担任唯一开发 COORD。用户已确认“三类入口自动调度”的总体原则：人工只提交一批指令或 MD；一条指令形成一条需求，一条需求可由多个角色完成。先不验证 QA 自动生成 Issue。
读取 docs/architecture/coord_intake_dispatch_phase1_design_20261103.md 和本交接单的 revision 2，核对权威规则、实际在途会话及用户改动。
先安排 PM/ARCH 将本专项整理为一页需求确认及实施概要，安排 INTEGRATOR 核实真实 COORD/角色调用与查询接口。保存原始指令、范围、验收场景、依赖及待决项，按准确版本交我批量审批；已有有效批准直接引用，不重复询问。审批前可开展已授权调查与方案编制，不启动未获准的新增实现范围。
人工不填写 YAML，由程序生成 issues/features/requirements 分类索引；必须有原文映射、版本去重、实际人工审批绑定及正式任务关联。确认范围后，再由 ARCH 拆工程任务、你实际派发，不能用 HEAD 读取器或计划别名冒充工程师运行。
按“人工触发单步 → 持续推进与恢复 → 定时服务”分段独立接受。长任务采用可查询作业，一个任务等待不锁住其他就绪工作；重复扫描、恢复和超时不能重复派发。
正式 QA 使用服务器锁定候选、独立沙箱、独立 Codex 和报告非作者复核，沿用原任务门禁。没有接受则保持待审/阻塞，不直接填 Done；本阶段不做真实 MCU 操作，也不启用 QA 自动换版。
普通技术问题由团队处理。先反馈实际执行入口调查、任务分工及本轮准确输入，再按检查点报告真实交付、证据、阻塞与下一动作；只有确需我处理的外部事项才提出。
```
