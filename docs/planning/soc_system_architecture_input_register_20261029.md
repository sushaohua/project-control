## 1. 用途与填写方法

本表汇总决定“模块怎样拆进程、进程如何通信、如何接入真实显示模块”所需的输入。现有事实仍引用各自原件；本表是索引和补充答复入口，不替代B0、正式协议或已接受任务。留空表示未确认，不表示默认批准。

用户可直接编辑第3节的“答复/资料路径”列。由相关Owner补技术依据，COORD记录实际确认人、时间、证据和影响范围；需要改变既有基线时按变更流程更新权威原件。岗位不等于已运行的Agent，本表也不派单、不改变任务状态。

**最新会话需求（2026-10-29）**：用户明确“两阶段开发”：第一阶段在VMware上尽量1:1运行SoC功能模块、进程与进程管理、通信和可见界面；第二阶段经编译工具链、启动部署及平台配置适配迁移到SoC。已选浏览器显示并要求它作为独立模块对接真实后台。具体见[两阶段孪生开发方案](vmware_soc_twin_development_plan_20261029.md)。已有离线HTML只可用于布局讨论，不算阶段一系统交付；具体目标进程划分仍由ARCH/Owner按已选业务接受。
