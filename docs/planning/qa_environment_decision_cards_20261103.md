# 独立 QA 环境与首轮执行问题卡

配套[独立 QA 流程](independent_qa_vmware_execution_flow_20261103.md)。四卡均已在当前对话通过问答工具提出并得到用户答复，以下保留原选项及准确选择，不需要用户重复回答。这些选择确认流程边界，不代表实际环境已核验或单次硬件操作已经获准。

## QA-Q01：VMware 环境

问题：独立 QA 的 VMware 环境采用哪种方式？

- A．从现有 VMware 克隆独立 QA 虚拟机，并冻结快照（原建议）。
- B．新建干净 VMware 虚拟机，重新安装全部依赖。
- C．使用现有 VMware，划定 QA 独占窗口并冻结快照。

**用户选择 C。**落实现有 VM UUID/快照、QA 数据与权限隔离、作者热部署停止和排他窗口；服务器独立源码及 Docker 构建要求继续适用。VM 账号、快照操作入口及可用窗口由 INTEGRATOR 核实。

## QA-Q02：首次完整验收候选

问题：首轮候选如何选择，如何衔接 Debug 和 921600 两项需求？

- A．先测当前服务器锁定版本，两项功能交付后进入后续增量轮（原建议）。
- B．等待两项功能交付，再进行首轮完整验收。
- C．先完成环境和用例准备，具体受测版本稍后指定。

**用户选择 B。**首轮完整验收候选必须包含两项实际交付、已接受契约及必要依赖，统一锁定 buildno。等待期间推进环境、用例、工具和交接适配准备，不将其误写为已完成完整验收。

## QA-Q03：台架物理能力

问题：真实硬件台架目前具备哪种条件？这决定运动、供料、调平等用例能否验收。

- A．已有 MC、TH 和完整机械/传感器设备，可安排受控运动测试。
- B．只有 MC、TH 单板及部分传感器，先验证通信和可观察功能。
- C．现有设备情况尚未确认，先由集成人员盘点（原建议）。

**用户选择 A。**用户确认设备具备完整机械/传感器，可安排受控运动；实际执行仍核对板卡/探针身份、传感器、机械可用空间和限位、保护状态、排险及独占窗口。当前加热 0% 约束继续，不以此选择授权实加热或修改保护参数。

## QA-Q04：MC/TH 固件部署

问题：首轮 MC/TH 固件部署采用哪种方式？现有板卡、探针身份核验和硬件门禁仍须执行。

- A．自动生成制品与烧录计划，由授权人员确认并烧录，随后自动测试（原建议）。
- B．完成探针白名单、板卡核验及窗口授权后，由受控脚本烧录 App 并测试。
- C．首轮保持现场固件，只部署 AP；缺少固件来源的项目标记阻塞。

**用户选择 A。**程序生成两板 App 制品、命令及地址/校验计划；授权人员复核执行并留存物证，核验实际部署后启动自动测试。无人值守自动烧录不在本轮范围，Bootloader 不随 App 测试重刷。

## 剩余工程核实项

以下交对应角色调查，不要求用户先提供全部技术细节：实际 VM/账户/快照入口和窗口；两块板卡及两支探针身份；业务与两路调试端口稳定映射；网络/浏览器版本；两板可重复 Docker 构建合同；发布序列/buildno 分配入口；采集和物理效果观察能力；需求期限及手册冲突；QA 发现交给 COORD 的真实收件通道。

核实中遇到只能由用户提供的凭据/权限、资源窗口或产品取舍，再提交新的具体问题卡。凭据通过受控环境提供，不写入本文件或测试物证。
