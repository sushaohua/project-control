## 目标

每次交付读一张切片卡和三行结果。门禁从实际运行自动生成结果，工程人员只在失败、阻塞或交接需要行动时补一句。保留机器证据供独立 QA 与排障使用。

```text
受测候选  printer-soc@<短提交>
阶段与结果  Docker QA · 阻塞，候选与构建证据不一致
当次证据  <本次 verdict.json 链接>
```

成功时第二行只有阶段和结论。候选还未锁定时明确显示「候选未锁定」。预检通过按现有预检语义显示，各级结果仍由原门禁判定。换人时只补接手人需要处理的事项，例如台架占用或待授权的操作。

## Token 消耗与改法

取 `SLICE-06` 第 3、4 轮独立 QA 的已有 `codex.jsonl`。两轮分别记录约 49 万和 61 万输入 Token，扣除其中的缓存输入后分别约 8.2 万和 8.6 万。这里统计的是两轮独立 QA 的输入，工程、协调会话及实际收费未纳入。两轮合计 64 次命令读取，返回约 0.8 MB 文本。体积最大的几次读取来自整段方案、规则、代码和门禁日志。

- **派单给指针。** 沿用切片卡，给当前验收项、候选及当次证据入口。返修只交付阻断项、定位与一次证据链接。
- **先看可判定结果。** 独立 QA 先收现有裁决、验证范围和机器一致性结果，按验收项查变更及必要证据。从相关文件、行号或失败窗口展开，遇证据缺口时按需继续查原件。
- **复用已验结果。** 用现有续跑判据复用输入与证据完全匹配的结果。候选或验收范围变化时重新验证。机械冲突交脚本裁决，独立审阅检查业务覆盖、异常和安全。

## 实施范围与限额

| 顺序 | 工作 | 精确路径及验收 |
| --- | --- | --- |
| 1 | 在既有证据核对中增加切片修订号与 profile 比对。沿用 `_verify_qa_evidence(qa_dir, spec, commits, proof) -> str`。候选、摘要或验证范围错配时按现行证据冲突路径返回 `BLOCKED`，说明错配项。 | `tools/gates/slice_gate.py`。现有正常与异常样例覆盖通过、旧提交、摘要错误、错误 profile 或 revision。 |
| 2 | 从已核对的裁决读取受测提交、阶段、结论和证据链接，巡航显示三行。`_build_review_prompt` 提供验收项、机器比对结果和精确证据指针。返修包只交失败阶段、具体原因和一个证据入口。 | `tools/gates/slice_gate.py`、`tools/workflow/run_slice_batch.py`、`tools/test_v2_gates.py`。通过、失败、阻塞及未锁定候选的措辞可区分。既有后台等待、零误扣返修和幂等续跑通过回归。 |
| 3 | 在现有切片卡自检路径试行三行交付。验收已有交付包要求时，自动保留现有打包程序的产物 SHA-256，使用既有检查命令核对实际文件。报告写明软件 profile 和额外产物证据来源。 | `slices/SLICE-07.yaml` 仅在 COORD 确认该切片尚未启动且安全交接时更新一处交付文字。若已启动，推迟启用试行。 |

本轮 `project-control` 最多改 4 个现有文件，另维护本方案。优先复用裁决 JSON 与打包输出。一张任务卡和一个裁决入口即可定位证据。当前四阶门禁和真机授权仍按现行规则执行。Docker 镜像升级、宿主额外产物的通用接入以及串口报文解析器属于后续可单独评估的工作。

## 验收与切换

- 在独立工作区执行 `cd project-control && python3 -m unittest tools.test_v2_gates`。新增断言集中于本次结果展示和候选错配回归。选择一次已有候选按实际门禁方式核对摘要与原始证据。
- 用试行切片的正常独立 QA 记录输入 Token、缓存输入、命令读取次数和大段读取原因。复用当次证据与门禁结果评估改善，节省效果以同等审阅范围下的数据为准，原始证据仍可按需展开。
- 待用户批准后在独立工作区实施。当前 COORD 轮次结束并确认安全交接后再启用。按既有规则保存原始日志，转交时只提供三行摘要与确有需要的待处理事项。
- 如新输出影响接续，回退本轮变更提交，沿用原裁决与已归档证据。
