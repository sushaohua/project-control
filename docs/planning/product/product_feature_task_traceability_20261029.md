# 产品功能到任务对照表（PM 主责，ARCH 配合）

**用途：**把 PM 产品目录的 44 项产品目标追踪到需求候选、工作包、任务和证据，供 COORD 排序和后续拆卡。本表为工作区对账草稿：未改变既有任务状态，也未代表独立 Codex QA、正式收件或整机首版范围已完整批准。状态为对账时的快照，执行前以原任务卡与准确候选证据为准。

- [TASK-001 产品需求工作包](../work_packages/TASK-001_收敛%20FDM%20产品需求和验收.md) 是全部条目的共同需求收敛入口，不是每个功能的专属实现任务。PL-01/PL-02 是增量范围和拆解入口；本表未虚构新的 REQ、工作包或任务卡。
- 逐行状态根据用户接受的 PM 建议更新；七项已选子范围以 U-D01 为准，原建议待决定的完整产品功能仍待决定。不能理解为取消已确认的温度增量、VMware真实进程或浏览器界面。单项要分类为首版必做/后续/暂不做，必须记录决策人、范围、版本和依据；技术团队可提出建议但不得代替用户决定。
- “无编号级任务对应”表示现有任务卡和工作包按 PM 精确编号未检出直接引用；不能据此断言不存在相近任务或相关实现。证据列只列已找到且范围明确的材料；“未定位”不等于已证明从未做过。
- 需求栏的 `PM:` 与 `SOC:` 是不同目录命名空间，尤其 HMI/NET 同编号不代表同一功能。SOC 简写参照原映射，范围如 `UPDATE-001～004` 保留原写法。三项无显式 PM 编号映射单独标记；语义候选须 ARCH 确认。
- 依赖栏引用 PM 目录的技术支撑作为**候选**，并列出 SOC 映射中的能力缺口。每行软件、硬件、外部条件的分类和完整性均未逐项确认；未列出不表示不需要，需由 ARCH 和相关 Owner 逐项补全。目录中的芯片、算法、设备和性能指标不是已确认硬件事实；软件、硬件及外部服务各自的型号、Owner、接口、资料和验收条件仍需核实。缺失条件只阻断相应功能，不阻断其他已就绪工作。
- 逐项产品验收证据尚未建立本表到准确候选/实测的完整绑定；源文件和卡片状态不构成功能通过。温度或基础设施证据不得提升为混色、实体触摸屏或完整产品的通过。
