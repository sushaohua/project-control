## 怎样逐步变成开发计划

1. PM 按 PL-01 从本表挑下一增量，给使用场景、正常/失败结果和排除项，范围由 HUMAN 决定。查询试点已单列，不再次等待全产品确认。
2. ARCH 按 PL-02 核对真实输入与接口，未知先安排调查；每张实现卡有批准输入、产物、范围、独立预期与接收者。
3. COORD 只派满足 Ready 的卡。下一个增量可优先考虑“一份真实样本的小作业”，但是否采用、样本/宏/材料和执行完成能力须先确认。
4. 远期继续保留工作包，不提前虚构全部代码细节或工期。首轮实际交付后再估算投入，并明确假设与外部等待。

范围检查时逐项追到 `FEAT → REQ/ADR/接口版本 → 任务 → 实际候选 → 测试证据`。AI 协作演示、主机模拟、工程样机、产品 V1 分开，不以其中一项完成代替其他项。

本次共展开 **73 项候选功能**；尚无商业版本整表批准。当前步骤和工作包见 [[AI_SoC_协作方案/03_实施步骤与首个闭环]]，当前任务状态见 [[AI_SoC_协作方案/看板]]。
