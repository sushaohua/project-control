# COORD 总控执行清单

这是现有COORD的统一执行入口，配套[验收门禁](../../.agents/rules/delivery_and_coord_gate.md)及[机器队列](coord_autorun_queue_20261029.yaml)。角色和任务由COORD实际拉起，不需要用户逐个转发。当前建立了队列和检查入口，AUTO-01/02尚未实现；不得声称自动后台服务或服务器沙箱QA已经运行。

## 3. COORD的循环算法与停止条件

1. 读取入口、当前规则、队列、实际卡片和运行记录；检查是否已有唯一COORD、在途Agent、租约和设备占用。
2. 如AUTO能力尚未接受，先落实AUTO-01/02；不能用队列检查脚本假装会启动Agent。可在实际工具会话内先人工执行同一流程，逐项留下真实记录。
3. 优先处理在途任务/等待回执/退修；从剩余任务中选择所有直接前置的准确产物已接受、资源可用的任务。最多两张实现卡并行，QA/评审也要独立环境和资源。
4. 实际启动相应作者/Reviewer，记录会话ID、任务/revision、沙箱/工作区和反馈通道；通过工具wait/poll接收结果，不造角色签署。
5. 对同一候选执行服务器基线、独立沙箱、内容门禁及完成条件；所有必需接受和收件齐全才由COORD推进正式状态，继续第3步。
6. 两次有证据纠正仍失败，或必需外部输入/有效授权缺失，保存检查点、准确错误和解除条件；其他无关就绪任务可继续。只有确需用户处理的事项才提出，技术实现由团队处理。
7. 会话结束前保存游标、实际Agent/候选/等待事件，不宣称后台自动续跑。常驻部署须由AUTO-02实际演练重启恢复后另行接受。

任务表与检查入口不是权限控制器。可信QA判定必须来自作者/COORD不能伪造的runner/服务端作业身份与受保护结果接口；保护策略及实际写权限由AUTO-01核实部署，离线JSON或本地脚本exit0不足以替代。

## 5. 本次交付边界

本轮交付的是规则、队列、模板、检查工具及AUTO实施任务，不替代AUTO任务本身的实现/服务器推送/沙箱部署验收。当前工作区还有其他会话的未提交改动，不因编写规则而一并提交推送，也不改变TWIN-01现有正式状态。实际服务端验收记录产生后由COORD按新门禁收件。
