# 第一次启动与日常使用（当前 Marlin 路线）

> **当前使用入口（2026-10-29）：** [两阶段执行总表](../planning/vmware_soc_twin_task_execution_20261029.md)与[主看板](../../.agents/kanban/KANBAN.md)为当前接续入口。第一阶段在VMware运行真实服务/管理/IPC/浏览器界面，第二阶段迁移并实板实屏验收。旧文中的MS/CLI启动与历史模拟记录仅保留其原范围；新服务尚未交付，不存在可照抄运行的完整孪生启动命令。

本页提供复制指令；唯一执行顺序和依赖是 [[AI_SoC_协作方案/03_实施步骤与首个闭环]] 与当前 MS 卡。打开笔记不会启动 Agent。岗位可按实际工具顺序执行，也可在明确委派与隔离条件满足后并行，汇报真实执行方式。

## 1. 打开入口和看板

打开 [[AI_SoC_协作方案/00_开始这里]]、[[AI_SoC_协作方案/看板]]，保留负责项目的主对话。默认最多两个实现任务并行；你只需查看成果、卡点和下一步。

### 1.1 指定唯一 COORD 并登记执行方式

角色是岗位，Agent 是执行者；工程师也是角色。岗位原件见 [[AI_SoC_协作方案/02_模块与Agent职责]]。先在选定的主对话发送以下指令：

```text
本对话的主 Agent 担任本项目唯一 COORD。
先登记实际主对话名称/入口或工具会话标识，并同步到看板的 coord_session。
记录本轮选用的人工转交或本轮主子反馈方式到 execution_mode；没有选定时保留待定。
只登记能够定位的实际入口，不编造工具 ID；已有 COORD 时先完成交接，避免两个协调者同时写状态。
任务按当前卡准确 revision 执行；登记岗位、实际执行者、检查者和反馈位置。
当前先完成角色/交接方式登记并汇报缺口，不启动开发、不安装依赖、不操作设备。
```

再明确本轮用哪种执行方式：

| 方式 | 怎么使用 | 怎样收到结果 |
| --- | --- | --- |
| 独立对话人工交接 | 你将 COORD 的准确派单交给另一个对话 | 执行者交记录，你通知原主对话读取 |
| 主对话委派子 Agent | 你明确要求 COORD 为满足条件的卡创建子 Agent | 本轮通过工具收取子消息/结果，同时保存证据 |

默认不启动后台服务；主对话本轮结束后，要再次发送继续指令。文档修改不代表已经指定 COORD 或创建执行者。采用子 Agent 方式时可发送：

```text
本轮允许你按当前任务卡委派独立子 Agent 并收取反馈。
先核对工程访问和派单五项；只安排一张满足条件的小卡。
把实际岗位与 Agent 分开登记，作者与检查者分开。
在已有授权范围推进，缺必要资料就报告；不把本轮委派理解为常驻后台服务。
```

派单和回执格式统一见 [[AI_SoC_协作方案/templates/角色任务提示词]]；准入规则见 [[AI_SoC_协作方案/04_公共看板与读写协议#4.1 派单前必须明确的五项|派单五项]]。

## 2. 提供已经能运行的工程

```text
SoC 运行环境：VMware Ubuntu（SSH 访问）
MC/TH 开发环境：Windows/WSL（见环境交接）
工程总目录：
MC Marlin 目录：
SCM 自定义 Marlin 目录：
SoC 工程目录与 forward 入口：
VMware SSH 地址/实际设备枚举：
目前编译、启动命令：
该机器怎样访问：
```

不知道的写待提供。提供路径后先核对能否访问，不自动授权所有源码写入、系统安装或真实设备操作。

## 3. 先交接，再确认查询接口

```text
在已登记的 COORD 主对话中，读取当前 AGENTS.md、协作入口、B0、职责文档、看板和 MS-01～06。
按本轮选定方式派单；每卡核对五项，登记实际执行者、检查者、输入版本及反馈入口。
先按 MS-01/02 交接真实 MC/TH 私有工程与固件配置/制品，独立复现准确构建和台架启动记录。
登记真实固件、工作区差异、工具链、配置/制品哈希；QA 独立复现，操作按 HW-G 门禁。
ARCH 先按 MS-03 复核 RX、版本/温度缺口；必要时 ENG-MC 按 TASK-005 MCQ 补接口和验收，再由 ENG-FWD 的 MS-04 核对 USB 直通双向字节通道。
MS-01/03 先只读查源码与记录；MS-02 在授权的隔离输出目录构建运行，MS-04 只发已核查的只读探测并采样。
ARCH 的源码调查先交允许探测，再由 MS-04 的 ENG-FWD 交真实实收样例；缺资料写待提供，固件缺口按 ENG-MC/ENG-TH 准确微步交付。
接受主控最小对接约定，QA 先准备独立输入和预期。
任务状态只由你按实际交付证据更新；人工占用期限、预算与检查点前收取进展，未续领不得继续新增修改。
QA 作者卡由独立 Reviewer 检查方法/报告，必需评审逐项记录，不靠角色名算已检查。
```

完成标志：MS-01～06 的交付及检查达到各自验收，准确路径已登记；仅用户报告成功不能把 MS-02 设 Done。

## 4. 按已授权范围完成 SoC→MC

```text
先由 MS-18 交可构建的 SoC 主机工程，再按 MS-07/08/09/10 推进查询与恢复。
MS-09 使用 MS-06 的独立故障预期；MS-20 交统一主控候选，MS-11 再独立验收。
派单前补准确工作区、写路径、契约版本、实际执行者与检查者、反馈入口、预算和资源。
FWD 只改 SoC 适配，SIM 只改已授权模拟/故障工具，QA 独立检查。
不等完整 BSP、UI 或三类总线；不新增 SCM 功能，不改 MCU 运动规划。
报告绑定集成候选版本，标 MC-only，不称双 MCU 通过。
```

## 5. 再加入 SCM

```text
MS-12/13 可提前核查 SCM 来源与主机可行性；MS-19 先接受独立样例和故障预期。
MS-14 从控实现等 MS-11 主控出口通过，再接 MS-15/16；MS-21 交统一候选，MS-17 独立验收。
优先复用真实定制逻辑，缺外设才做受限模拟，先接受范围和差异。
由 MC 转发查询和错误，SoC 不直连 SCM，不向 AP 旁路注入成功响应。
验证正常、单端故障和恢复，QA 独立报告 MC+SCM 的覆盖与未验证项。
缺少接口则登记扩展依赖，不为通过测试造 API 或擅改生产固件。
```

MS-22 另验实际团队交接，优先使用 MS-01/02 的真实记录；首阶段完成须有 MS-11、17、22 三份有效结果，不能只看软件查询成功。

MC/SCM 构建配置、状态和生命周期分别记录；具体规则见 [[AI_SoC_协作方案/08_双MCU模拟器与联调验收]]。

## 6. 每天怎么用

| 目的 | 发给主对话的话 |
| --- | --- |
| 看进度 | 读取当前任务及交接证据，汇报成果、卡点和下一步。 |
| 继续 | 在已授权范围按当前 MS 依赖选择下一项满足 Ready 条件的任务，不批量启动工作包。 |
| 增加功能 | 为这个功能登记需求与验收，再拆准确子任务，评估接口影响。 |
| 暂停/恢复 | 暂停或恢复指定任务；保存检查点，确认旧执行者和设备状态后再交接。 |
| 看失败 | 给我失败日志、版本和复现步骤，判断是环境、通信、模拟还是接口资料问题。 |

只有 COORD 更新状态；其他角色交自己的产物/事件。新的产品取舍由你决定，例行模块实现按已授权范围推进，不把每个技术细节都变成确认问题。后续 TASK 工作包继续拆小卡，不回到旧的批量派单命令。

## 当前运行方式与起步核对

参照 [[开发调试环境搭建（带SoC）.canvas]]：Windows/WSL 管 MCU 开发和调试，VMware Ubuntu 跑 SoC 程序并经 USB 直通访问 MC；/dev/ttyUSB0 是已选设备名，实际枚举/稳定链接及权限由本轮核对，Windows COM8 不同时监听。TH COM6 只用于独立诊断，业务经 MC USART6 转发。

当前没有真实 SoC 板卡，Canvas 的 C302X/网口/调试线是后续部署。既有 MC 日志和 Bootloader 升级记录不代表业务查询已可用；MS-03 调查、MCQ 接口建设/验收、MS-04 实收和 MS-05 对接接受按各自条件推进。每名执行者只持一张微步票，验证和独立检查后才推进下一步；这仍是人工记录，不自动启动调度或唤醒服务。

最近加入的微步/QA 资料继续使用，正式状态由唯一 COORD 投影；失败回退仅本步差异并保留原有用户修改。一次输入齐全的授权文档更新可按批次推进，不重复申请已给出的授权。硬件/保护/生产操作仍按实际任务与门禁处理。
