# 中间链路 (MC ↔ TH) 帧采集机制与观测边界说明

## 1. 采集架构与观测拓扑

在真实硬件在环（HIL）测试环境下，通信链路划分为物理直连段与板间中继段：

```text
[SoC AP (VMware Ubuntu)]
       │
       │ 物理直通 CH340 串口 (/dev/ttyUSB0, 115200 8N1)
       ▼
[MC 主控 (AT32F435VGT7)]
  ├── USART2 (上行接收/回发)
  └── USART6 (下行中继转发, 921600 8N1)
       │
       │ 板间硬件跳线 (PA4/PA5 ↔ PB6/PB7)
       ▼
[TH 从控 (AT32F423CCT7)]
  └── USART1 (板间通信串口, 921600 8N1)
```

## 2. 观测手段与证据边界披露 (Transparency & Disclosure)

依据独立审计原则，特此对两段链路的观测数据来源作出真实披露：

### 2.1 外部观测端点 (AP ↔ MC)
- **直接观测手段**: 宿主机操作系统直接通过 Linux `termios` 驱动与 `/dev/ttyUSB0` 进行物理双向 I/O 交互。
- **采集数据**: 包含完整的请求发包（Raw TX Hex）、原始应答（Raw RX Hex）、单调时钟 RTT（精确至微秒）、内核时戳及返回码。
- **证据级别**: 物理抓包一级直接证据。

### 2.2 中间中继端点 (MC ↔ TH)
- **物理事实**: MC 与 TH 之间通过板载杜邦跳线连接（MC USART6 与 TH USART1，波特率 921600 8N1）。
- **观测方式与间接证明链条**:
  1. **原生路由头状态机演变 (Hop & Route Control)**:
     - AP 发出的原始版本查询帧：`55AA01030501040002000000B218`（声明 `hop_limit=4`, `route_ctrl=0x00`）。
     - AP 最终收到的 TH 版本应答帧：`55AA030106020304020010000200010055AA77885AC05663070000001D95`。
     - 该回包明确标识 `hop_limit=3`（经 MC 减 1 转发防环）、`route_ctrl=0x04`（`ROUTE_IS_ROUTED` 置位）且 CRC-16 重新计算为 `0x1D95`。这证明了报文经过了中间路由器的帧头变换。
  2. **硬件 SWD 寄存器级单端故障注入断言**:
     - 在保持 AP ↔ MC 串口连接不变的前提下，使用独立硬件探针通过 SWD 总线直接写 TH 物理寄存器 `0x4001100C = 0x00000000`（切断 TH USART1）。
     - 此时发起 TH 查询立即在 300ms 内触发 `TIMEOUT` 退出；而发起 MC 查询依旧正常响应（RTT 7.5ms）。
     - 随后使用探针将 TH 寄存器恢复为 `0x0000202C`，TH 查询立即恢复正常。
     - **该物理注入结果排除了 MC 伪造本地应答的可能**，确切证明了请求必须穿透 MC 并成功抵达 TH 芯片内部的 USART1 外设。
- **证据缺口声明 (Evidence Limitation)**:
  - 当前工作台架**未在 MC ↔ TH 跳线上接入独立物理逻辑分析仪或示波器探头**进行物理波形直采。
  - 中间链路的真实性是建立在“外部抓包 + 协议头多跳变换校验 + SWD 硬件级外设切断/恢复实测”这一闭环因果链条之上的，而非裸线信号直采。
