# ISSUE-20261102-05 协议总规范与三端实现一致性整改专项

## 1. 冲突事实核查清单
1. **总规范权威定义**：
   - 依据 `ap_mc_formal_protocol_v2_0_multidevice_routing_draft_20261015.md` Rev 2.0.3 §5.1 与 §5.2，`CMD_ACK = 0x00`（载荷 4B），`CMD_NACK = 0x06`（载荷 3B：1B `error_code` + 2B `expected_seq`，小端）。
2. **派生 ICD 偏差**：
   - `docs/interfaces/ap_mc_th_readonly_cascade_icd.md` 第 202 行将 `CMD_NACK` 错误定义为操作码 `0x00`、载荷长度 `0x0002`，与总规范冲突。
3. **MCU 固件实现偏差**：
   - MC 与 TH 在 `minimc_proto.h` 中均定义 `#define MINIMC_CMD_NACK 0x00U`，且 `build_nack_resp` 仅组装 2 字节载荷。
4. **SoC AP 内部冲突**：
   - `contracts/twin/telemetry_types.h` 正确定义 `MINIMC_CMD_NACK 0x06U`；
   - `core/host/query.h` 错误定义 `CMD_RESP_NACK = 0x00`，导致 `query.cpp` 将操作码 `0x00` 当作 NACK 处理。
5. **测试用例偏差**：
   - `test_harness/test_cases/cascade/query_cases.json` 中 `CAS-NEG-008` 注入了 `cmd_id = 0x00` 且载荷为 2 字节的旧报文。

## 2. 闭环原则
- **总规范权威不可逆**：绿地设计无历史兼容包袱，严格以总规范为准，禁止逆向将代码中手误的 `0x00` 漂移写入总规范。
- **职责物理边界封锁**：各角色严守各自仓库代码边界，由 COORD 全程推进调度。
