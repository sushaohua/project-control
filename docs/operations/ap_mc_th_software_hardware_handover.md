## 4. 目标配置与当次实物核验

“目标配置”来自现有登记，不表示本次已部署或实测。每次run复制本表填写实物结果、实际人员、时间和证据。已有确认参数直接引用，只补真正缺项和实物核验。

部署前阶段只核实本阶段必需的实物身份、接线、供电/电平、目标映射与静态配置；本次部署后的初始化/收发结果留到阶段C/D填写，不能因尚未部署而虚填或形成前置循环。

| 核对项 | 已登记目标 / 来源 | 本次实物核验 |
| --- | --- | --- |
| AP环境 | VMware Ubuntu模拟SoC/AP，不等于目标SoC已验证 | 待确认：VM身份、系统架构/依赖及程序实际运行 |
| MC / TH芯片 | AT32F435VGT7 / AT32F423CCT7 | 待确认：各板号、PCB修订、芯片/UID及识别记录 |

| AP设备 | 登记/dev/ttyUSB0；用户内核日志为ch341-uart，不据此补确切适配器型号 | 待确认：实际路径、USB身份及到MC的映射，不凭tty序号认板 |

## 7. SOP与证据的必需要求

CR-08在现有SOP补齐准确候选的完整命令、cwd、工具版本、唯一目标、地址、预期输出、停止点和恢复方法；有占位符的示例不能作为可执行SOP签收。

1. 前检候选哈希、板卡/探针/串口映射、接线、供电/电平，登记单一操作者和排他窗口。
2. 明确部署路径。升级路径必需或风险可达时先接受CR-07；采用SWD仍列隔离依据。涉及U盘按HW-G1等待真人确认；首次烧录按HW-G2人工复核地址与完整命令。本轮不改运动、加热、PID、限位参数。
3. 向已确认目标部署准确文件，记录实际命令/退出码/日志，核对启动及部署身份。
4. 先AP↔MC的GET_VERSION/PING，再MC↔TH及完整级联；AP侧115200，中间段921600，不能把全链路配置为921600。
5. 核TH真实源响应和MC透明转发；观测工具不得争抢UART。中间段缺观测时列缺口，由ARCH/独立QA确定是否满足证明要求，禁止自判通过。
6. 按已接受用例执行失联、错误/无关帧、超时及恢复。故障工具另核接受和授权；USART去使能仅证明通信静默，不能记成真实掉电；寄存器写成功不等于链路恢复。
7. 非预期串口输出或硬件行为按HW-G3停止，由工程师判断；保留失败现场，按授权恢复并核真实通信，释放资源、交接剩余问题。

每例事先绑定用例/预期版本、超时与恢复期限、执行次数和判据，由ARCH、端Owner及独立QA接受。RTT使用单调时间，明确起止点，不套用未经证实的典型值。记录实际设备、串口配置、UTC毫秒/单调时间、方向、逐帧TX/RX Hex及src/dst/flags/cmd/seq、精确载荷/长度、CRC；跨端时钟未同步时列时间源与偏差限制。采集器缺字段先补足或接受替代方法，不能编造日志。

正常查询零有效关联响应判失败；噪声/回显/MC伪造TH响应不能算成功。负例按正式预期判断，坏CRC等可要求静默丢弃，不统一要求NACK。MC仅处理协议允许的帧级路由字段，不改业务seq/payload，不降级G-code。
