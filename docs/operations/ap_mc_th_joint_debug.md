# AP–MC–TH 工程联合调试操作约定

本约定由 CR-08 装配、CR-09 执行；独立验收由 CR-10 执行。协议依据为 [只读级联 ICD](../interfaces/ap_mc_th_readonly_cascade_icd.md)，分工与颗粒度见[当前重排](../planning/workflow_replan_20261028.md)。本文是计划，不是本次已进行台架操作的记录。

1. INTEGRATOR 提交候选清单：AP 源码/程序、MC/TH 源码/固件/配置、ICD、独立用例和采集器逐项版本及 SHA256。CR-12 的复用矩阵需接受所消费的检查与限制。
2. COORD 登记一名操作者、设备标识、端口/波特率、两只探针及占用窗口；按卡核既有 HW-G 授权。只有部署路径和操作授权明确后才部署。升级模式有依赖或可达风险时先消费 CR-07 的准确接受结果。
3. 操作者核对实际部署与启动身份；无法读回的身份写未知，不能以文件存在代替上板。AP `/dev/ttyUSB0`→MC USART2 为 115200 8N1；MC USART6↔TH USART1 为 921600 8N1，具体设备与配置每次按登记核对。
4. 先用 GET_VERSION/PING 检查 AP↔MC：命令、src/dst/flags/seq、精确长度与载荷符合 ICD，保留原始 TX/RX 和带毫秒时戳的实际结果。
5. 再检查 MC↔TH 转发及回程：请求、TH 真实应答与 MC 回传可关联，核 Hop、routed 标志与 CRC。中继不代 TH 生成业务响应。观测工具不得争抢 UART；不能采集某段时明确观测缺口，交 ARCH/独立 QA 确定是否满足用例证据要求。
6. 再运行 AP→MC→TH→MC→AP 及已接受的失联/恢复用例。软件工具用于离线预检须标明 host-software；正式正常 HIL 零有效关联回复判失败，负例按事先定义的预期判定。寄存器写入或断线等故障注入另核实际授权及恢复读回。
7. 首个失败即保留原始数据；按“AP发送/MC接收 → MC转发/TH接收 → TH应答/MC接收 → MC回传/AP匹配”定位到段。端 Owner 提供小范围修复，生成新候选哈希；不在台架会话中越权修另一端，不靠伪响应获得绿灯。
8. 一轮使用一个冻结候选；日志按 run/case 索引，正文只写预期、实际、失败段、根因及修正版本。工程调试到约定上限后交检查点。稳定后 CR-10 使用同一候选独立验收；QA 自己的报告由非作者按既有规则复核，无代码变更时无需为了复核再完整重复台架。

任务 run 至少附：操作者/各端参与者、候选清单及哈希、实际设备/部署/启动身份、命令与退出码、用例与原始记录、是否实际故障注入及恢复结果、未执行项和限制。退出时释放串口/探针，保留失败现场说明；恢复动作限已授权范围。
