# 第一次启动、接续与日常使用

**你只需要向现有COORD说明目标、查看成果、处理真正需要你的事项。** 任务分配、拉起工程师Agent、独立验收、退修和接续由COORD负责。详细的负责人操作方法见[09手册](09_How-to_项目负责人操作手册.md)。

本页提供复制指令，不是实时看板。实际任务、暂停、执行者和验收以任务卡、最新运行/交接记录及COORD核对结果为准；不因读到旧文档就重新开始已有成果。2026-10-29修订前的07原件保存在[本次更新记录](../evidence/guides_07_09_update_20261029/README.md)。

## 1. 先找到负责协调的会话

| 对象 | 负责什么 | 你怎样使用 |
| --- | --- | --- |
| 你（HUMAN） | 产品目标、优先级、实际资料和必要授权/实物确认 | 说明想达到的结果，处理COORD提出的具体缺项 |
| 现有COORD | 队列、实际Agent、依赖、资源、独立验收、收件和进度 | 把执行指令发给它，由它统一安排 |
| 本项目助手 | 解释术语、整理文档、帮助理解汇报和准备提示词 | 需要解释或调整计划时使用，不自动接管COORD |
| ARCH、工程师、INTEGRATOR、QA | 设计、代码、集成和独立验证 | 由COORD实际拉起，不需要你逐个新建对话或转交每张卡 |

如果已有Agent在工作，沿用负责分配任务、维护看板的那个COORD。不要同时把“担任唯一COORD”的指令发给多个Agent。确需更换时，先保存交接、核对旧执行者和设备占用，再切换唯一状态写入者。

不知道谁在协调时，先给项目主会话发：

```text
请先核对当前项目的实际COORD、正在运行的Agent和任务、已有交付及资源占用。
保留已有分工，不重复派单；已有唯一COORD时，说明应由哪个实际会话接续。
读取已有暂停/交接记录，不擅自恢复我明确暂停的任务。
这次先核对现状，不因这条询问启动开发或硬件操作。
请用普通人能理解的话告诉我下一步。
```

只有确实没有COORD时，再指定一个实际会话并登记真实入口和反馈方式。角色名、计划别名、模型和文档不是Agent已经运行的证明。

## 3. 给现有COORD的一次性启动指令

**准备开始或继续授权内工作时，把下面整段发给现有COORD。** 本手册的编辑、打开或阅读本身不会启动任务。

```text
你继续担任本项目唯一COORD，我是非技术项目负责人。

先读取README.md、AGENTS.md，以及：
project-control/docs/planning/coord_autorun_tasklist_20261029.md
project-control/.agents/rules/delivery_and_coord_gate.md
project-control/docs/planning/communication_modules_ownership_20261029.md

核对已有在途Agent、实际任务卡及revision、授权、交接/暂停记录和资源占用。
保留已有分工和历史成果，不重复派单，不擅自恢复我明确暂停的任务。
核实AUTO-01/02的实际接受范围，先落实缺失的运行能力，不把计划当部署结果。
仍未解除的TWIN-01候选疑点另留run复核，保留原报告；受影响字段不交给TWIN-02冻结。
再按实际依赖推进TWIN业务任务，由你拉起对应ARCH、工程师、集成和独立验收Agent。
Fast DDS由ENG-DDS维护，D-Bus由ENG-DBUS维护，代码和依赖保存在当前soc-ap仓。

每张卡完成作者自检、准确候选提交/推送核实、独立Codex在独立沙箱从服务器固定提交重建验收、QA报告非作者复核、必需Owner接受和收件后，再接续下一张。
失败回原作者按新候选修复，不跳过验收；按现行重试上限保存检查点并处理。

第一阶段在VMware运行真实模块、目标进程/进程管理、真实IPC和浏览器交互，并接真实MC/TH。
第二阶段复用业务源码、契约和界面资源，适配SoC并实板验收；不保证仅改编译器即可成功。
目标板资料缺失只阻断依赖它的工作，不阻止目标无关VMware开发。

已有授权和确认不重复询问，普通技术问题由团队解决。
只有必要资料/授权缺失、产品取舍或达到失败上限时，向我提出具体问题。
需要我操作电脑或实物时，一次说明一步、预期看到什么及如何判断结果。
按检查点汇报交付和证据、验证层级、未完成项、真实运行任务、下一动作及是否需要我处理。
```

如果当前只想整理文档或了解现状，使用第1节的核对指令，不必发送执行指令。已有用户暂停要求仍有效；恢复时明确说“恢复哪个任务”，由COORD检查接续条件。

## 4. 一张任务怎样做完

**核对输入 → 派单并拉起实际Agent → 作者实现/自检 → 提交并推送准确候选 → 独立服务器沙箱QA → 非作者复核QA报告及必需Owner接受 → COORD收件 → 下一张。**

| 你关心的事情 | 团队必须怎样处理 |
| --- | --- |
| 会不会只有任务表，没有执行？ | 记录真实会话、任务、工作区/沙箱和实际回执；没有运行写未启动 |
| 测的是否是交付代码？ | 锁服务器完整提交，重新获取源码/契约/测试工具，不复制作者未提交改动或install缓存 |
| QA是否独立？ | Codex实际运行在独立沙箱；新对话、目录或Git worktree不足以证明隔离 |
| 失败是否会被忽略？ | 保留原报告，回原作者修复，按新候选复验；未通过不释放对应下游 |
| 是否需要我每次审核？ | 普通技术收件由独立QA、必需Owner和COORD完成；你看阶段成果并处理必要外部事项 |

最多两张实现卡并行，物理UART、探针和台架按单一操作者窗口排他使用。版本、日志和任务字段由团队记录，不要求你逐字段手填。

## 5. 两阶段最终要看到什么

| 阶段 | 可见交付 | 范围边界 |
| --- | --- | --- |
| 第一阶段：VMware | 可操作的浏览器界面，真实MC/TH数据；真实后台服务和IPC，启动/停止/重启、故障/过期/恢复可演示并有证据 | 离线页面、CLI和软件替身只证明各自范围，不能单独代表应用孪生完成 |
| 第二阶段：SoC | 同一业务/契约/UI来源的目标构建部署；实屏/触控/外设、资源/延迟和故障复验 | VMware通过不代表SoC驱动、显示或性能通过；平台差异另记 |

按已接受业务增量逐步实现，不把产品目录全部功能一次变成承诺。MC/TH仍是真实硬件；“模拟SoC”不允许中继伪造下游应答。

## 6. 每天怎么用

以下话都发给现有COORD，不用分别找每个工程师：

| 目的 | 可以直接发送的话 |
| --- | --- |
| 看进度 | 请汇报本轮交付和证据、验证范围、未完成项、真实运行任务、下一动作及是否需要我处理。 |
| 接续工作 | 请读任务卡、队列和最新交接，在已授权且未被我暂停的范围继续，按依赖逐卡闭环。 |
| 有Agent正在工作 | 请先核对其实际任务、版本和占用，接续原分工，避免重复启动或抢写。 |
| 查看演示 | 请展示当前已验收候选的真实界面/设备链路，说明数据来源、异常表现和未覆盖范围。 |
| 增加功能 | 请先登记需求、非目标和验收，评估接口/任务影响，再给我必要的产品取舍。 |
| 指定暂停 | 请暂停【任务ID或范围】，保存检查点、候选和设备状态，记录等待我恢复的范围。 |
| 指定恢复 | 请核对【任务ID或范围】的旧执行者、环境和输入；具备条件后恢复，保留历史记录。 |
| 会话中断/更换AI | 请从README、当前卡和实际交接恢复，核对在途进程和资源，不仅依赖旧聊天。 |

## 7. 自动推进的实际边界

有工具和实际反馈时，COORD可以在一次会话内连续派单、等待、收件和推进。会话结束后能否继续，取决于AUTO-02已部署并验收的实际能力；队列文件、提示词或一段回复不证明后台仍在运行。

运行器、可信服务器QA和沙箱未落实时，COORD先落实对应准备任务。需要临时接续会话时，你发“按最新交接继续”即可，无须重发所有任务；明确暂停的项目须先由你明确恢复相应范围。
