## 指令 1

【需求】组织完整 Web HMI basecase 与增量真实闭环验收，先确认并固定单 VMware 台架的编译部署流程。

### 目标与范围

由 COORD 查重并确定已有或新增的正式承接任务，组织同一锁定组合上的完整验收。覆盖 `BASE-01～27` 全部适用断言、跨功能旅程 `J-01`，以及 `DELTA-DBG`、`DELTA-BAUD`、`DELTA-COMB` 三组增量；正常、相关负例和恢复分别展开、计数、执行并记录。整改方案的 `HIL-01～06` 是映射和重点检查，不能代替完整 basecase。

核实 TWIN-47～50 的准确交付及实际接受范围；TWIN-46/TWIN-50 的软件或 PTY 接受不代表本轮真实 HIL 已通过。不因卡片 Done 或标题带 HIL 就省略真实硬件测试，保留历史软件签署。

### 前置：编译部署执行确认单

INTEGRATOR 先只读核实当前主机、唯一 VMware、Docker、AP/UI、MC、TH 工具链及现有构建部署脚本，提交一套推荐执行顺序。每步明确实际执行位置、执行者、命令及工作目录、准确输入、输出路径和哈希、成功条件、失败停止点与恢复办法。

方案覆盖服务器取件、依赖核验与复用、AP/UI 和双固件构建、组合与制品清单、传递和部署、旧证据归档、停旧和资源释放、启动及健康检查、双 Debug 采集启动时机。核实部署脚本是否隐式重编译、复用旧二进制或清理旧日志，保证最终部署身份与本轮接受的制品一致。

只对确需用户决定且确有可行替代方案的事项提出最多三道选择题，每题给出选项、推荐项、时间/台架占用影响和理由；不把一般技术参数拆成大量提问。用户确认后，将步骤、工具、配置及核验方式固定到现有执行流程；每轮更新候选提交、制品哈希和实际设备映射。流程实质变化时说明差异。

### 执行与闭环证据

- INTEGRATOR 汇总轻量提测交接：任务/revision、各仓完整提交、组合版本、用例/工具/契约版本、构建部署入口、设备/固件身份、端口映射、排他窗口及证据目录。缺少实际工具或接口时登记缺口，由对应角色补齐，不把计划当成已部署能力。
- 受控 Runner 从服务器独立取得准确候选，在独立 Docker 中完成适用构建和软件检查；授权台架执行者在唯一 VMware 和真实 MC/TH 上按受控步骤完成浏览器及 HIL 采证。独立 Codex 会话只读审阅同一候选及客观证据，不直接连接硬件。先安全预检及正常流程，再执行相关负例和恢复。
- 涉及固件的用例，以真实业务帧和 `[MC-DBG]`、`[TH-DBG]` 调试口原始日志核对闭环，关联同一目标、命令、请求/响应及新鲜状态；区分受理 ACK、入队与真实执行完成。MC 本板处理不强求 TH 日志；TH 级联核对 MC 接收/转发、TH 实收/执行/回复、MC 返回接收以及 AP 的匹配结果。
- Web/API 结果、调试日志与适用测量/物理效果随同归档并对账。运动、回零、调平、供料和作业完成不能仅凭日志、ACK 或逻辑坐标通过；查询类核对真实来源及样本一致性，纯软件断言不强加无关 MCU 操作。
- 采集先于本轮启动及动作，记录设备与固件绑定、时间源、boot epoch、丢失/截断及关联依据。记录不足时保持相应范围未判定或阻塞，不补造日志，也不直接把采集缺口判作业务失败。
- 保留 BASE-24 实际拔业务 USB 子例；软件解绑或 SWD 关闭 USART 不能替代。AP↔MC 与 MC↔TH 断连分别归因并验证恢复。调试关闭、慢读和满缓冲子例按预期单独判断，不要求被主动关闭的日志仍完整输出。

### 缺陷处理与交付

发现缺陷立即保留现场和原始证据，由 COORD 登记、关联和安排修复；仅阻塞依赖该缺陷的用例，其他独立可测项继续。编译/启动缺陷先查重关联 `20261105_soc_ap_build_and_startup_issues.md`，不重复派修。修复形成新候选后按差异复验和必要回归处理，保留既有 run，不拼接不同候选冒充整轮通过。

最终提交逐例结果、BASE/DELTA 正负与恢复覆盖统计、准确候选和部署身份、软件与真实 HIL 的分范围结论、缺陷/阻塞及原始证据索引。必测范围缺证据时不能宣布整轮通过；台架或工具暂不可用不构成删项或降为 Mock/PTY 的理由。

COORD 首次回执简短列明本单收件编号、承接任务、编译部署确认单负责人、材料缺口及下一检查点；该回执不替代用户对执行流程的确认。
