# 真机 HIL 穿刺与缺陷分诊规范 (`hil-and-issue-triage`)

本技能在批次切片完成 `SW-Verified` 到达 **Human Gate #2** 时启用，指导 `INTEGRATOR`、`QA` 与 `COORD` 完成物理硬件闭环与问题归并。

## 1. 真机 HIL 准入与物理安全红线
1. **单次物理授权**：执行固件升级、上电、回零、运动或加热前，必须先获得人类明确授权；常规固件更新走 MiniMCProto v2 OTA，探针仅限首次刷 Bootloader 或救援（核准 MC App `0x08020000`、TH App `0x08004000`）。
2. **零虚拟化底线（HW-G5）**：严禁使用 PTY、Loopback 或模拟器替代 板级描述指定的真实 UART（当前 `/dev/ttyS1`） 真实单片机；串口异常、异响或温控异常立即停机保现场。

## 2. 四方关联物证链采集（升级 `HIL-Verified` 必备）
同一测试请求必须采集并绑定以下四方客观证据：
1. **节点固件身份（HW-G7）**：AP / MC / TH / Bootloader 锁定的 40 位 Commit SHA、制品 SHA256 与现场协议读回版本；
2. **业务入口记录**：真实 Helix、IPC 或 API 的请求/响应；
3. **物理串口原始帧**：带毫秒时戳的双向 `Raw Hex TX / RX` 逐帧对账（有效关联回包为 0 直接判失败）；
4. **板端真实动作/状态**：`[MC-DBG]`/`[TH-DBG]` 真实触发日志及传感器/限位/温控实测变化，随后执行断连/坏帧负例与恢复验证。

## 3. 缺陷根因去重与分诊（解除 `NON_HUMAN_SUBMITTER` 死锁）
- 无论人类、测试脚本还是 Codex 发现的真实 HIL 缺陷，均按 **根因调用链** 去重归并（同一协议错位引发的多个表象合并为单一定向切片或返修项）。
- 明确区分 **环境/设备阻塞（`BLOCKED`）** 与 **源码缺陷（`REJECTED`）**：串口未插、台架占用或权限不足记为环境阻塞，绝不消耗工程 Agent 的代码返修轮次。

## 按业务能力选择物证

C308L真实UART取板级描述；不要求USB转串口。身份查询、相机、存储、运动与升级分别定义正负配对物证，身份查询不得编造动作日志。资源排他包含UART、屏幕/触控、相机/ISP/编码通道和数据卷。每项结果绑定应用、SDK/镜像、MC/TH的相应来源；不把历史VMware通过沿用为当前板级结果。
