# MS-18 准备 Ubuntu SoC 主机工程

## 目标

提供在 VMware Ubuntu 可构建、启动、正常退出的最小 SoC 工程，已有工程优先复用。

## 输入与写入边界

在 `soc-ap` 中从空应用目录建立最小 Ubuntu 主机入口。用户已提供 VMware SSH 别名 `vmware` 与串口 `/dev/ttyUSB0`；本轮候选采用 C++17/CMake、配置化串口路径，只构建/启动/优雅退出，不打开串口、不实现查询协议、不依赖目标 BSP。构建入口为 CMake，写入范围仅限本卡白名单；不安装系统依赖。

实际映射：`soc-ap/CMakeLists.txt`、`soc-ap/core/host/**`、`soc-ap/config/host.env.example`、`soc-ap/tests/host/**` 与 `soc-ap/README.md`。`build/host/` 为本地生成目录，不纳入源码交付。读取 B0、本卡与相关已接受输入；参考报告只作线索。

## 验收与交付

独立工作目录可以按同一命令构建并运行最小入口；可配置端点入口存在但不实现查询协议；记录工具版本、退出码、日志和产物哈希。已有代码只登记/补必要缺口；独立检查人与作者分开。

交付：最小 SoC 主机工程、准确构建/启动/停止入口与复核结果。运行卡附实际命令、退出结果、日志、版本组合与制品摘要；文档卡附准确文档版本与来源/评审。候选 commit、diff、合入版本只在适用且实际产生后填写。向登记的 COORD 交位置并取得回执；共同行为见 [[AI_SoC_协作方案/templates/角色任务提示词|交付格式]]。

当前从空应用目录建立的本地候选及构建记录见 `soc-ap/docs/host/ms18_local_candidate_validation.md`。本地构建/冒烟通过不等于 VMware 验收；MS-01 依赖、VMware 实机运行和独立评审/QA 尚未完成，任务状态保持 Backlog。
