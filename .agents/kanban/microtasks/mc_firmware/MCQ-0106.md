# MCQ-0106 主控MC实现至TH板间双向业务代理转发(USART6/USART1)

## 目标

在 `mcu-p3/motion-controller-mcu`（AT32F435VGT7）固件中打通 AP $\to$ MC $\to$ TH $\to$ MC $\to$ AP 的板间代理转发通路：
1. **识别目的地址为 TH（`dst_id == 0x03`）的 MiniMCProto 帧**：
   - 当 AP（`src_id == 0x01`）发送针对 TH（`dst_id == 0x03`）的查询/命令请求时（如 `CMD_VERSION_GET (0x03)`、`CMD_GET_VERSION (0x01)` 或透传指令），MC 识别该帧需要转发给从控 TH。
2. **通过 USART6（921600 8N1）向从控 TH 下发业务探测/命令**：
   - 利用已有 `forward_uart_send_line` 或相应接口向 TH 发送探测（如 `"M115\r\n"` 查询版本或携带有效指令）。
   - 在 USART6 接收链路（DMA / IDLE 判帧）等待 TH 回传（设置硬件保护超时计数，严禁死等）。
3. **回传封装 MiniMCProto 应答帧**：
   - 捕获到 TH 在 USART6 的回包（如 `ok2`、`FIRMWARE_NAME:...` 或温度数据）后，MC 构建合法的 MiniMCProto 响应帧：
     - `SOF`: `0x55 0xAA`
     - `src_id`: `0x03`（TH）
     - `dst_id`: `0x01`（AP）
     - `flags`: `0x06`（`IS_RESPONSE | PROTO_V2`）
     - `cmd_id`: 与请求帧匹配的 `cmd_id`
     - `seq`: 严格回显原请求帧的 `seq`
     - `payload`: 包含 TH 固件版本数据（如 `proto_ver: 2.0, fw_ver: 1.0` 或截取/映射之字符串载荷）
     - `CRC-16`: 完整小端 CRC-16/CCITT-FALSE
   - 通过 USART2（`minimc_proto_send`）回传给 AP。
4. **编译与打包**：
   - 执行 `make -C mcu-p3/motion-controller-mcu pack` 达到 Exit Code 0，成功生成 `build/fw_mc.bin`。

## 严格编码规范（c_cpp_coding_standard.md）

1. **单函数 $\le 50$ 行**：新增自研函数必须控制在 50 行内，复杂逻辑拆分 static 辅助函数。
2. **入参 $\le 4$ 个**：函数参数严禁超过 4 个。
3. **零动态堆内存分配**：严禁 `malloc`, `free`, `new`。
4. **显式指针与数组索引**：严禁 `*dst++ = *src++`，统一使用数组下标递增。
5. **防御性空指针校验**：所有函数入口首行执行 Guard Clause 检查指针有效性。
6. **硬件轮询强制超时**：硬件等待必须设置计数器递减退出，严禁空 `while(!FLAG);`。
