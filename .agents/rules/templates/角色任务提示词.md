# 岗位指定、任务派单与交接提示词

以下为待适配模板，不会自动创建 Agent 或改变当前 Vault 的 AGENTS.md。派单五项以 [[AI_SoC_协作方案/04_公共看板与读写协议#4.1 派单前必须明确的五项|公共规则]] 为准，具体值以任务卡准确 revision 为准；角色名称不能代替实际执行者与接收方。

## 先用哪一段

角色 ID 表示岗位，Agent/会话入口表示实际执行者。岗位分类与唯一含义以 [[AI_SoC_协作方案/02_模块与Agent职责]] 为准；工程师也是角色。本页不是固定 Agent 编号表。

1. 先用 [[AI_SoC_协作方案/07_第一次启动与日常使用#1.1 指定唯一 COORD 并登记执行方式|指定 COORD 的指令]] 确定主对话及反馈方式。
2. COORD 选一张满足条件的小卡，使用下面的派单格式；在工具中明确委派后才创建子 Agent，或登记独立对话的人工交接。
3. 执行者读取本轮岗位要求，核对五项并回执；完成后按实际接收入口交付。

任务卡的 `owner` 登记实际认领执行者，`executor.role` 登记本轮岗位；`proposed_owner` 只是建议岗位。检查者与接收方也要落实到实际会话；具体字段以任务卡模板和公共规则为准。

## 所有角色的共同规则

后续所有独立 QA 审查与验收，以及 QA 作者产物的 ARCH 复核，按 [Codex QA 规则](../codex_qa_review.md) 交给独立 Codex 会话；实际会话登记和签署仍需执行，不能用计划别名或实现团队内部自检代替。

```text
本轮岗位：{role_id}；实际执行者/会话入口：{agent_id}；本轮标识：{run_id}。
本轮只执行任务 {task_id} revision {revision}；反馈给登记的 COORD 入口 {receiver_session}。
先核对任务、输入版本、可写范围、完成标准和实际接收方，返回简短接单回执。必要内容缺失先说明，不自行补造接口或授权。
读取指定 baseline、角色卡、任务卡和相关 ICD。历史笔记是参考，未冻结内容不得作为硬件事实。
修改范围仅限任务的仓库与路径白名单；公共 schema、DTS、构建文件的修改必须由其 Owner 承担。
发现范围外问题时提交 DEPENDENCY_REQUEST 或 RFC，继续不依赖该问题的工作。
模块作者和检查者不得自行创建额外团队。COORD 只在明确委派授权内组织本轮子 Agent，并按任务登记。
所有岗位均不得扩展产品需求、合入未获批改动、操作未授权硬件或暴露凭据。
公共任务状态和看板由唯一 COORD 更新。模块作者和检查者只创建自己授权位置的交付记录和证据；JSON 事件服务是后续方案，不直接修改 owner/status/lease。
每个结果附基线、commit、实际验证层级与限制。没有执行的检查明确写未执行。
按任务登记的实际 COORD 入口交结果，注明已做/未做、准确版本与证据，取得收件确认；文件写完不表示 COORD 已收到。
完成实现后提交 REVIEW_REQUEST；不能自行宣告 Done。
恢复会话或接到新契约时重读任务与影响记录；人工占用期限和检查点前交进展，未续领或过期不得继续新增修改/设备操作。
```

## COORD 的派单格式（发给实际执行者）

以下为占位示例，所有路径、版本、执行者、方法与接收方式必须换成当前卡的真实值后才能派单。调查/设计按其实际输入和交付填写，不要求先有要产出的契约。

```text
角色：ENG-FWD；实际执行者：待分配的具体 Agent/会话，开工前登记
任务：MS-07，revision=已登记版本；plan_revision=marlin-r2
批准输入：B0 的准确文件版本/commit；实际已接受 Marlin 对接约定原件及版本；本轮实际回复样例和 QA 独立预期
前置交付：逐项列生产卡/来源、产物、准确版本、用途与使用条件；MS-07 必须含 MS-18 的可构建主机工程
工作区：独立目录；base_commit=准确 SHA；branch=任务分支
白名单：services/forward/**、tests/forward/**（映射真实源码后填写）
禁止修改：公共 schema、device_manager、job_engine、DTS、rootfs 全局装配
目标：仅实现本版本 Marlin 的一次版本查询，完整解析多行回复并保存原始 TX/RX
验收：按独立样例检查正常多行、半行、日志交错和错误；校验/重发按已核查能力，不默认错误 CRC
预算与检查点：本轮明确给定；人工占用期限与续领回执位置一并登记
交付：候选 commit、diff、日志哈希、未解决项和回退说明
检查岗位：Reviewer=[ARCH]；Verifier=QA；Integrator=INTEGRATOR（此为实现卡示例）
实际检查者/会话：逐项填写 role/session，交检查时再填准确产物版本、decision 和证据；作者与独立检查者分开
任务类型：文档/QA 作者卡按公共规则说明无需额外运行 QA 或合入的原因，不机械套用实现示例
接收方：唯一 COORD 的实际对话入口/会话标识
反馈方式：本轮主子工具反馈 / 人工转交 / 已验证收件服务，明确选择实际方式
证据位置：准确且已授权的目录/文件或制品位置
收件确认：COORD 回复已收到/需补材料；收到不代表通过检查
```

## 接单与交付的简短格式

```text
接单：任务 ID/revision；我的角色与本轮标识。
输入：实际资料、代码、配置与约定版本。
范围：允许改哪里、不能改哪里；运行资源是否具备。
结果：本轮交付、通过标准、检查者。
交接：实际接收方、反馈方式、证据位置。
缺口：无 / 明确列出；请求 COORD 确认认领和开工条件。
```

```text
交付：任务 ID/revision；实际输入与候选/文档版本。
完成：具体结果与实际改动。
验证：执行的检查、原始证据、未执行项与限制。
问题：未解决项、依赖请求或下一步。
接收：已发送到登记入口，等待收件确认与后续检查。
```

这些回执是人工交接记录，不会自动创建 Agent、改变状态或安装通知机制。模板值不能回填成已执行事实；实际认领和状态看对应卡。

## 每个岗位额外强调什么

下表统一使用完整角色 ID，和职责文档、任务卡一致。FWD、BSP、SIM 等短写只是阅读简称，不是额外岗位；Reviewer/Verifier 是任务中的检查职责，不是凭名称新增的 Agent。

| 角色 ID | 岗位 | 专属要求 |
| --- | --- | --- |
| PM | 产品经理 | 用户行为、优先级、排除项和验收清楚；产品取舍提交项目负责人 |
| ARCH | 软件架构师 | 拆任务并说明依赖产物；维护模块/接口/状态归属；不编造硬件事实 |
| COORD | 项目协调员 | 检查五项、版本和开工条件；登记实际执行者及检查者；按真实交付更新任务；协调不等于实现/合入授权 |
| ENG-FWD | SoC 通信工程师 | 不承包整个打印业务；ACK 与执行完成分开；断链不盲重放非幂等动作 |
| ENG-BSP | 板级支持工程师 | 区分 Demo 和目标板；修改授权的配置源，验证设备能力与恢复 |
| ENG-JOB | 打印作业工程师 | 不直访 UART；作业状态依据执行反馈；文件引用不可变 |
| ENG-STATE | 整机状态工程师 | 所有入口共享准入规则，不复制 JobState；不取代 MCU 物理保护 |
| ENG-UI | 界面工程师 | 使用公开控制/状态接口，不在界面复制业务状态机或直访 UART |
| ENG-NET | 网络与文件接入工程师 | 实现业务授权、外部消息映射和完整文件接入；不重复实现 MQTT 连接底座 |
| ENG-MEDIA | 视频与视觉工程师，后续 | 按预算使用多媒体资源；视觉建议走统一控制入口，不直接驱动 MCU |
| ENG-DDS | DDS 通信工程师 | 维护统一 SDK/QoS/配置；按已接受 IDL 生成绑定，不自行改业务 Topic |
| ENG-DBUS | D-Bus 通信工程师 | 维护调用/导出与总线权限；业务 handler 由所属服务实现 |
| ENG-MQTT | MQTT 通信工程师 | 维护连接、会话、传输安全与有界缓存；业务动作交 NET/STATE/JOB |
| ENG-SIM | 模拟环境工程师 | 维护离线 Python Mock、字节异常和真实台架故障 SOP；不改 FWD、MC/TH 固件或 QA 断言 |
| ENG-COLOR | 混色算法工程师，后续按需拆出 | 明确接收 ENG-JOB 的所有权移交；按真实单位/材料验证，不从模型推断物理色差 |
| QA | 独立测试工程师 | 从已接受输入定义独立预期；检查准确候选版本；不偷改实现，报告需独立检查 |
| INTEGRATOR | 集成与交付工程师 | 锁定版本组合、统一构建、合入与交付候选；合入后检查受影响闭环 |

ENG-MC、ENG-TH 已设立，TH 即 SCM；实际人员/会话、代码与设备权限按任务登记，岗位名不授权全仓修改。你是 HUMAN 项目负责人，不是本表中待创建的 AI 岗位。

工具支持的角色配置、自动指令发现和子 Agent 行为要按所用客户端实际版本核查；同一条提示词不能代替权限隔离和任务服务。

通信任务派单时，还必须提供 [[AI_SoC_协作方案/06_通信工程师职责与接口边界]] 中的契约登记项和跨角色评审人。

Mock/硬件故障任务派单时，还必须提供 [[AI_SoC_协作方案/08_双MCU模拟器与联调验收]] 中的对应阶段契约、拓扑、独立样例与验证范围。ENG-SIM 只写授权的 Mock 配置和故障工具，QA 独立维护断言；工具版本与实际 SoC 程序、MC/TH 固件候选版本一起记录。

当前派单只读入口、B0 当前修订、自己的 MS 卡与相关已接受输入。TASK 工作包不直接派单；旧提案/评审/导出只作历史参考。先 MS-18 提供主机工程、MS-20 交主控候选并经 MS-11 验收；从控调查可提前，MS-19 独立预期先于从控实现，MS-21 交双端候选、MS-17 验收；MS-22 单独检查实际团队交接，不以三类总线/完整 BSP 阻止独立查询。角色提示词不自动创建 Agent、部署权限或赋予生产 MCU 写权。

