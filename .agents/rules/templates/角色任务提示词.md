以下为待适配模板，不会自动创建 Agent 或改变当前 Vault 的 AGENTS.md。派单五项以 [[AI_SoC_协作方案/04_公共看板与读写协议#4.1 派单前必须明确的五项|公共规则]] 为准，具体值以任务卡准确 revision 为准；角色名称不能代替实际执行者与接收方。

## 先用哪一段

后续派单粒度按[当前任务重排](../../../docs/planning/workflow_replan_20261028.md)。一次只给本票、相关契约段落及准确输入哈希、范围、验收和收件入口；同一作者可继续相关任务复用未变上下文。同一候选允许非作者批次审阅并逐项签署；不要复制完整聊天或重复整库阅读。历史微步名称不要求每个内部函数单独启动会话。

角色 ID 表示岗位，Agent/会话入口表示实际执行者。岗位分类与唯一含义以 [[AI_SoC_协作方案/02_模块与Agent职责]] 为准；工程师也是角色。本页不是固定 Agent 编号表。

1. 先用 [[AI_SoC_协作方案/07_第一次启动与日常使用#1.1 指定唯一 COORD 并登记执行方式|指定 COORD 的指令]] 确定主对话及反馈方式。
2. COORD 选一张满足条件的小卡，使用下面的派单格式；在工具中明确委派后才创建子 Agent，或登记独立对话的人工交接。
3. 执行者读取本轮岗位要求，核对五项并回执；完成后按实际接收入口交付。

任务卡的 `owner` 登记实际认领执行者，`executor.role` 登记本轮岗位；`proposed_owner` 只是建议岗位。检查者与接收方也要落实到实际会话；具体字段以任务卡模板和公共规则为准。

## 所有角色的共同规则

后续所有独立 QA 审查与验收，以及 QA 作者产物的 ARCH 复核，按 [Codex QA 规则](../codex_qa_review.md) 交给独立 Codex 会话；实际会话登记和签署仍需执行，不能用计划别名或实现团队内部自检代替。

```text
本轮岗位：{role_id}；默认模型：gpt-6-luna（如获批准覆盖，注明批准依据和实际模型）；实际执行者/会话入口：{agent_id}；本轮标识：{run_id}。
本轮只执行任务 {task_id} revision {revision}；反馈给登记的 COORD 入口 {receiver_session}。
先核对任务、输入版本、可写范围、完成标准和实际接收方，返回简短接单回执。必要内容缺失先说明，不自行补造接口或授权。
读取任务卡准确revision、当前有效授权、已接受ICD、父任务相关能力条件和独立预期，核对实际输入哈希。历史笔记和分析报告只作参考，不将静态配置当板上事实。
实现作者接单前须核对 `read_sources`、`protocol_input`、`source_baseline`、`dispatch_binding`、`depends_on` 和 `write_scope`/`allowed_paths` 中引用的 ARCH 实际方案及本轮输入，确认其任务范围、版本/hash和允许路径与当前卡一致；不得以 COORD 口头“已检查”替代。缺少实际 ARCH 交付或出现技术冲突时回交 ARCH，COORD 不自行探索业务源码或为通过脚本改写技术字段。
缺前置能力、blocked=true、租约过期、路径/设备占用冲突时停止受影响动作，记录DEPENDENCY_REQUEST；不由活跃会话单边补造下游能力。
帧结构、业务命令、请求关联和硬件闭环分开判断；正常场景无有效响应为失败，故障注入按其预期判定。
修改范围仅限任务的仓库与路径白名单；公共 schema、DTS、构建文件的修改必须由其 Owner 承担。
发现范围外问题时提交 DEPENDENCY_REQUEST 或 RFC，继续不依赖该问题的工作。
模块作者和检查者不得自行创建额外团队。COORD 只在明确委派授权内组织本轮子 Agent，并按任务登记。
所有岗位均不得扩展产品需求、合入未获批改动、操作未授权硬件或暴露凭据。
公共任务状态和看板由唯一 COORD 更新。模块作者和检查者只创建自己授权位置的交付记录和证据；JSON 事件服务是后续方案，不直接修改 owner/status/lease。
涉及代码的作者按 project-control/.agents/rules/code_documentation_standard.md 自检：全部新增或修改的说明性注释及 docstring 使用中文，补齐模块/公共接口/关键逻辑说明；Python Runner、检查器与脚本同样适用。
每个结果附基线、commit、实际验证层级与限制。没有执行的检查明确写未执行。
按任务登记的实际 COORD 入口交结果，注明已做/未做、准确版本与证据，取得收件确认；文件写完不表示 COORD 已收到。
代码/QA 交付按 project-control/.agents/rules/delivery_and_coord_gate.md §5.4 执行四项效率纠偏；复验使用现有正文说明前次报告、本轮变化、整改对应项和必要回归，先程序预检，再按需读取原始证据；非阻断建议可随批准保留，不扩大本票验收范围。
完成实现后提交 REVIEW_REQUEST；不能自行宣告 Done。
恢复会话或接到新契约时重读任务与影响记录；人工占用期限和检查点前交进展，未续领或过期不得继续新增修改/设备操作。
```

## COORD 的派单格式（发给实际执行者）

以下为占位示例，所有路径、版本、执行者、方法与接收方式必须换成当前卡的真实值后才能派单。调查/设计按其实际输入和交付填写，不要求先有要产出的契约。

```text
QA策略：{qa_policy}；新任务用streamlined-v1，普通QA、QA作者产物独立ARCH，额外岗位开工明确，旧卡不静默迁移
岗位/实际会话/run：{role}/{actual_session}/{run_id}；模型：gpt-6-luna（覆盖时填实际模型及COORD批准依据）；唯一COORD：{coord_session}
任务：{task_id} revision={revision}，template_version=2026-10-27；只执行该票阶段
授权：引用当前或既有有效授权，写明范围；不重复索要已具备授权
输入：{协议/接口/源码/配置/独立预期的准确版本、哈希、接受记录}
前置：{每项depends_on对应产物/能力/接受版本}；父任务相关门禁={实际映射}
状态：blocked=false；实际租约/检查点={已登记值}；当前不是模板自动开工
工作区/范围：{真实仓库、分支、base_commit、开工diff SHA256、具体文件白名单/禁止项}
资源：{隔离输出、实际设备/端口/探针、占用者和期限}；角色名不授予设备使用权
目标/非目标：{一个结果及排除范围}；涉及AP/MC/TH时列每个节点能力提供票
跨节点协作：{契约票、节点任务、工程联调票、独立组合验收票}；不制造循环前置
验收：{命令/cwd、必跑测试组和最低非零case、正常/异常预期、期限及证据层级}
成功标准：{命令语义、src/dst/flags/cmd/seq/长度或对应业务断言}；不能只看CRC或exit0
交付：{准确候选commit/diff/清单SHA256、制品哈希、实际运行记录、失败/未执行项}
独立检查：逐项登记{岗位/platform/model/实际session}；QA Codex默认gpt-6-luna；交付后再绑定同一候选、结论和报告SHA256
适用性：{verifier/integrator/HIL不适用的理由与依据}；不能靠删必需岗位绕过
收件：{COORD实际入口、传递方式、证据根/run位置}；收到不等于接受
回退：{仅本票差异与保护点}；不覆盖已有用户改动，失败按原始输出→根因→单点修复
接单回执：核对以上输入和范围后回复；任一必要条件不具备先报告缺口
```

## 接单与交付的简短格式

```text
接单：任务 ID/revision；我的角色与本轮标识。
输入：实际资料、代码、配置与约定版本。
范围：允许改哪里、不能改哪里；运行资源是否具备。
结果：本轮交付、通过标准、检查者。
交接：实际接收方、反馈方式、证据位置。
缺口：无 / 明确列出；请求 COORD 确认认领和开工条件。
```

```text
交付：任务 ID/revision；实际输入与候选/文档版本。
完成：具体结果、实际改动、准确候选commit/diff/制品及其哈希。
验证：逐例预期与实际观察、实际命令/cwd/退出码、必跑组/非零case、原始证据及其哈希；未执行项保持未执行。
适用范围：本票/离线/单板/组合/真实HIL分别说明；新候选不继承旧签署。
问题：未解决项、依赖请求或下一步。
接收：已发送到登记入口，等待收件确认与后续检查。
```

这些回执是人工交接记录，不会自动创建 Agent、改变状态或安装通知机制。模板值不能回填成已执行事实；实际认领和状态看对应卡。

工具支持的角色配置、自动指令发现和子 Agent 行为要按所用客户端实际版本核查；同一条提示词不能代替权限隔离和任务服务。

通信任务派单时，还必须提供 [[AI_SoC_协作方案/06_通信工程师职责与接口边界]] 中的契约登记项和跨角色评审人。

Mock/硬件故障任务派单时，还必须提供 [[AI_SoC_协作方案/08_双MCU模拟器与联调验收]] 中的对应阶段契约、拓扑、独立样例与验证范围。ENG-SIM 只写授权的 Mock 配置和故障工具，QA 独立维护断言；工具版本与实际 SoC 程序、MC/TH 固件候选版本一起记录。

当前派单只读入口、B0 当前修订、自己的 MS 卡与相关已接受输入。TASK 工作包不直接派单；旧提案/评审/导出只作历史参考。先 MS-18 提供主机工程、MS-20 交主控候选并经 MS-11 验收；从控调查可提前，MS-19 独立预期先于从控实现，MS-21 交双端候选、MS-17 验收；MS-22 单独检查实际团队交接，不以三类总线/完整 BSP 阻止独立查询。角色提示词不自动创建 Agent、部署权限或赋予生产 MCU 写权。
